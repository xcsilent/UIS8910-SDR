# Project working rules

- Follow the latest user request. Read `docs/project-state.json` and `docs/plans/goal-roadmap.md` before hardware work; recorded device state is not a live query.
- Current code is in `firmware/` and `tools/`. `tools/sdr.py` is the daily entry; `tools/build_firmware.py` builds the v0.1 AP/CP service and PAC without deployment using pinned `build-support/` inputs. `tools/build_capture.py` is only an older B5 research baseline.
- `tools/build_host_components.py` is the WSL Windows-host build entry; Ubuntu prerequisites and the separate native SDR++ MSVC scope are in `docs/building-wsl.md`. Preserve paired DLLs and deployed host manifests when building candidates.
- `archive/legacy-2026-10-23` is frozen history. Search/read it only for a specific missing fact. Never execute its runners in place or treat its plans, firmware labels or session numbers as current.
- Keep old project wrappers, probes, sweep runners and version-specific audit chains out of active directories. Extract a necessary shared implementation instead of restoring a whole historical branch.
- Keep `work/` regenerable and `outputs/firmware/current` unambiguous. A new candidate needs a distinct directory and must not be presented as already flashed.
- Current release and host entry points are `outputs/firmware/current/manifest.json` and `outputs/host/manifest.json`. The only retained release is v0.1. Historical firmware artifacts were removed at the user's request; small records retain their original labels. Never infer deployment from a build record. Preserve full local SDK/toolchains and the build-support inputs.
- Use the UIS8910 SDK and pinned ZW217 excerpts as primary references. `inputs/reference-source/predecessors` retains eight independently useful 8955/8810/8850e files; full predecessor trees are archived. Do not copy their register bit positions into UIS8910.
- Do not append per-turn history to current state/plans. Keep `project-state.json` compact; evidence stays in the six topic directories under records. Resolve retained historical paths through records/index.json; older metadata is in one local archive. Before cleaning `work`, consult its README: toolchains and current linked builds are not disposable caches. On2026-10-30 the user requested removal of original IQ/capture intermediates; records/retention retains historical indexes and retention.json, not payloads. Preserve final conclusions and do not restore the old raw retention gate.
- IQ transport follows the user requirement: raw bytes, no application CRC/header/ACK/retry; loss/corruption accepted. Do not turn historical wire audits, strict zero-loss or register coverage into new global gates.
- Check the current project with `python -B tools/sdr.py verify`; run additional focused build/tests when the change warrants them. Current checks must allow legitimate future state changes rather than freezing historical milestones.
