# USB raw IQ 实现与优化

## 当前结论

当前 v32 服务已部署并采用六个 8192 字节输出槽。RXCAPT DMA 写入 DDR，UDC DMA 从同一缓冲读取，USB 使用 Bulk IN；Windows 端用异步读池接收。配置与统计独立，数据面保持纯 raw IQ。

格式为交错 little-endian 16+16 位容器，每路有效 signed12 位位于 bits 15:4，每个复数样点 4 字节。系统保留长度、cache、所有权、完成和错误检查；不加入应用 CRC、包头、ACK 或重传，允许丢块和部分损坏。

当前实际 USB 供给约 30–32 MB/s。BW0/BW1 的自动等待为 250 µs，BW2–BW5 为 100 µs；宽档允许 scratch 丢弃和传输间隙，以 SDR 频谱轴、参考峰、刷新、改频和停止可用为目标。BW4/BW5 的名义采样率 30.72 Msps 需要 122.88 MB/s，USB 2.0 无法全量承载。

USB 调度、ACK 时序和 refill 微调已经按用户要求收口。历史统计、队列和固定源报告只作为原因定位证据；重新打开本分支必须先出现实际退化、功能故障或有明确收益的新测量。

## 验收口径

用户最新范围：不再测试USB无法持续全量承载的采样档位。当前新增通信验收仅BW0/BW1；BW2需要30.72 MB/s，实用基线30–32 MB/s尚无充分持续余量，暂不安排，BW3–BW5不做新增通信/吞吐测试。既有宽档部分输出能力保留，不追补测试。

影响USB或主机队列的改动只做有针对性的回归，先短采、必要时10秒；仅持续性新故障或明确需求才加长，不自动重跑60秒或整套旧实验。分别记录设备完成量、主机接收量、文件/消费者量、吞吐、CPU、scratch丢弃和错误。字节一致不表示没有采集间隙，无法定位的丢样保持未知。当前硬件Goal未激活，本页不是自动执行指令。

正常改频流程是停止、排空、配置、重新采集，不复位芯片。Windows、SoapySDR 和 SDR++ 共用同一库、频率表和数据格式。宽档不再追求全量实时传输；8+8 位和紧凑 12 位只有在设备端确实减少 USB 字节且收益超过 CPU 开销时才重新评估。
