# RF 软件范围与实测边界

v32已部署并核对generation，B3 1600/1500/1447/1400/1375 MHz通过完整有限参考，1350/1300 MHz当前条件未检出首音。1375 MHz成功时VCO码为1，不能用低码或cal_ready独立判断失锁或物理下限。[汇总](../../../records/rf/coverage-v32-b3-lower-summary.json)。当前主机交付的B3默认/Auto请求包络扩至1375–1920 MHz；它包含未逐点验证的位置，不是已证明的连续覆盖。

v31实机B3 1710/1680/1650 MHz已通过有限双音、TX-off和100 kHz改频跟随，见[记录](../../../records/rf/coverage-v31-deployment.json)。已部署v32和当前Windows DLL支持显式手动解限；仅保留uint32 Hz及100 Hz格式边界、原NV/锚点依赖。Soapy/SDR++默认使用下表生成的请求包络；下表不限制v32显式手动请求，也不表示芯片物理极限。

用户默认设置频率，Auto在B5/B8/B3/B40候选中择路。手动B配置是RF路由/NV/校准选择，中心频率独立传Hz，不要求落在标准LTE频段。27行原始表仅供候选，不再逐行接入。

当前发布一致性待修：下表来自C请求表，Windows C helper的B40上界为2790.625 MHz；Soapy/SDR++的C++ helper另有2786 MHz质量cap。共享表不等于所有入口边界完全一致，两者均不是芯片物理极限。面向使用者的合并频率结论见[性能页](../../performance.md)，具体修正候选见[维护者评审](../../maintainer-review.md)。

## 高价值实测

- B40/BW0已完成2400–2800 MHz步进5 MHz的81点测试，采用B210 TX gain55、RX gain40、8192B DMA分析：72点完整通过；2435、2440 MHz按用户要求作为环境影响下通过。2535/2545 MHz双音及改频跟随通过但TX-off对照不足；2540/2550 MHz单音在约82%/86%的DMA窗超过12 dB，未完成后续参考步骤，不将其解释为接收空洞。两台设备使用2.4/5GHz Wi-Fi双频天线，非校准功率条件。[汇总与逐点证据](../../../records/rf/coverage-b40-grid-2400-2800-summary.json)。
- 同一 B40/BW0 条件下，2000–2390 MHz 以 10 MHz 步进完成 40/40 个完整参考通过，覆盖当前 2000–2800 MHz 的离散证据带；10 MHz 间隔仍不排除窄空洞，也不等同芯片连续物理范围。[低频筛选汇总](../../../records/rf/coverage-b40-grid-2000-2390-summary.json)。
- B5/B8 在 880–940 MHz 的同条件对照支持现有 Auto 滞回：B5 在 880–910 MHz 明显更强，B8 在 920–940 MHz 明显更强，910 MHz 的 B8 未完整通过。现有 915/920 MHz 交接策略保持不变。[低频重叠汇总](../../../records/rf/coverage-b5-b8-overlap-880-940-summary.json)。
- 高频细化：2786 MHz完整通过；2787–2789 MHz开关、双音及100 kHz改频跟随仍通过，但峰突出度约8–12 dB。2800 MHz完整B40/B41对照均有TX相关响应与约200 kHz双音间距，峰突出度仅约1–2 dB，100 kHz改频仅跟随92.8 kHz。应记为明显退化，不能写成完全无接收或芯片物理上限；B41未改善该退化。软件Auto包络、完整参考质量和可检测响应须分开。[高端1 MHz细化](../../../records/rf/coverage-b40-grid-upper-2786-2789-step1-g55.json)、[2800 MHz跨路](../../../records/rf/coverage-b40-b41-2800-g55-d8192.json)。5 MHz网格不排除点间窄空洞；低TX增益下的2380/2390 MHz未检出不是上限，不恢复该结论。

- B40历史2.0–2.6GHz多个离散点通过；当前USB服务2.0/2.33/2.6GHz及部分更低点有证据。B40表外宽调谐必须保留，不能退回2300–2399.9MHz。约1.884GHz下侧和2.78GHz上侧历史结果有条件限制，未证明整段连续。
- B3覆盖补洞与B40重叠：1885MHz切换后参考、1900MHz必要对照已有证据，Auto采用保守余量；不是B3的裸芯片边界。[重叠证据](../../../records/usb/geometry-auto-1885-reference-summary.json)。
- B5低端687.5MHz通过，681.25MHz首音未识别；675MHz等失败不能区分PLL、片内模拟、板级前端及天线/参考限制。双组ready/VCO静态快照不足判成败。[阶段对照](../../../records/rf/lowband-v21-phase-comparison.json)。
- 900MHz同一有限TX比较：B5开关对比58.77dB通过，B8约7.37dB不足，两路弱峰频移可跟随，支持现有B5优先策略。TX日志有underflow，不将差值当校准灵敏度。[同TX证据](../../../records/rf/lowband-v21-b5-b8-shared-tx-900.json)。
- B8在970/985/990MHz有离散有效点，995MHz弱且未达门槛，999.9MHz首音未识别；仍不是芯片上限。[低频证据索引](../../../records/rf/lowband-README.md)。

新路径先代表点、参考开关、中心改频跟随，再向转折/边界扩展。未检出不得直接判芯片不支持。B1/34/38/39/41等历史代表点保留为按需补洞证据，不恢复全表盲扫。[已测路由](../../../records/rf/v5-summary.json)、[B40当前宽带对照](../../../records/rf/b40-v21-2600-closeout.json)。

## NV 与选择器

空洞请求链已进一步[原始/C组合验证](../../../records/rf/reference-b-gap-request-chain.json)：保留板级NV下，B3的field4确为RX端口1，B5/8为2/3；1.1/1.447/1.6/1.71GHz、BW0–5在-O0/-O2执行一致。B组名为calibration的回调目标0x453c实际按selector/slot应用表，不读请求频率或ready/VCO，不能当未还原的自主校准过程。B3后续0x38a8的24例也选择同一默认配置。该证据使用保留SDK镜像及历史NV，不是当前完整调用者/实机锁定证明；足以支持保留原NV、端口和1805MHz初始化锚点的有界B3实验候选，不足以广告空洞覆盖。先在1710MHz控制点与其下方一个代表点做参考识别，失败时不继续盲扫。

1.0–1.71GHz空洞的[v30离线核对](../../../records/rf/reference-rf-gap-assessment-v30.json)：当前PAC原始系数helper与C的30例一致，代表working频率没有系数回绕；这不是PLL锁定或接收证据。B3软件1710MHz下限为显式包络，低于1805MHz仍使用channel1200初始化锚点。B组模拟表按RXON field4选行，不能由相同系数算法推断同一通带。约1447MHz的原始45/61表项使用selector18，但已记录的原生查表无匹配NV/端口，不绕过门禁。下一步核对B3请求打包与模拟/校准分段，再决定有界候选；当前不扩展Auto或广告范围。

SDK默认NV含B7而本机历史运行NV缺B7、含B34行13；B41运行flag140改表为2535–2675MHz。每次新硬件阶段仍需实际查询，不把历史NV当实时状态。B18/19/26映射B5选择器和NV，不能据表名假定新模拟前端。

SPI/XCV逻辑地址、RF本地、CP别名、板外FEM RFFE地址分开，见[初始化链](init-sequences.md)与[PLL对照](pll-reference-comparison.md)。软件算术可写、PLL/cal_ready、模拟通路通过、指定外部RF实际接收是不同证据层次。
