# UIS8910DM SDR 改造技术性能报告

## 摘要

本项目将 Air724UG 模组中的 UIS8910DM LTE Cat.1 接收链改造成可由主机控制的原始 IQ 接收设备。设备保留厂商启动、校准和 RF 事务，增加采前中心频率/增益/带宽配置、RXCAPT DMA 采集、USB Bulk IN 原始传输以及 Windows、SoapySDR 和 SDR++ 入口。采集点位于数字接收/抽取链、LTE 解调之前，不是 ADC 直接采样，因此不依赖 SIM、入网或蜂窝协议栈。当前 raw 准备代码清除 RX_PRE.FIR_EN，不能据此声称所有数字滤波已经旁路。

当前发布基线是 v32 固件和 `outputs/host/manifest.json` 指向的 Windows/Soapy/SDR++ 组件。该基线已完成真实数据流、改频、停止排空和 10 秒空口 QPSK/OFDM 功能证明。RF 连续物理上下限、外部前端确切型号、ENOB、精确丢样位置以及宽档全量 USB 传输仍未验证。

报告快照日期：2026-10-30。本轮只整理既有证据，没有新增硬件测试。供国际社区阅读的[英文完整报告](technical-report.en.md)、[机器可读能力表](data/sdr-capabilities.json)和[性能图表](performance.md)与本报告配套。当前身份以[固件 manifest](../outputs/firmware/current/manifest.json)和[主机 manifest](../outputs/host/manifest.json)为准，历史记录不是实时设备状态。

## 1. 设备与改造目标

目标硬件是 Air724UG/UIS8910DM 模组。原设备面向 LTE Cat.1，项目不恢复完整蜂窝解调，也不把 GSM BCPU、ZSP 或 1090 MHz 扩展作为 SDR 首版依赖。改造目标是：

1. 保留厂商 RF 初始化和板级校准依赖；
2. 通过独立控制通道设置中心频率、增益和采样档位；
3. 从 RXCAPT 取得 DFE/FIR/抽取后的复数 IQ；
4. 通过 USB 2.0 High-Speed Bulk IN 送到 Windows 主机；
5. 为命令行、raw 文件、SoapySDR 和 SDR++ 提供同一套数据格式与 Auto 选路。

## 2. 系统架构

完整硬件/软件职责图、缓冲所有权图和切频时序见[系统架构](architecture.md)。数据路径为：`天线/板级前端 → 片内模拟接收 → 数字接收/抽取 → RXCAPT DMA → DDR → UDC DMA → Windows → raw/Soapy/SDR++`。AP 负责 USB 和主机控制，CP 驻留模块负责采集与 RF 请求，独立 RF 指令镜像执行寄存器事务。它是软件职责图，不是已经证实的芯片物理平面图；外部前端型号、连线、核时钟和完整片上内存容量尚未知。

数据面是纯 raw IQ，没有应用层包头、CRC、内容哈希、逐包 ACK 或重传。控制和统计走独立通道。设备在停止时先停采集、排空 DMA/USB 所有权，再允许改参重采；正常操作不复位芯片。

## 3. 固件实现

`firmware/capture` 和 `firmware/sdr_receiver` 负责 RXCAPT、DMA、环缓冲、UDC 队列和控制 ABI。采集 DMA 写入 DDR，UDC DMA 读取同一缓冲，保留长度、cache、所有权、完成和错误检查。宽档采用允许丢弃的 scratch/环策略，以维持 SDR 软件刷新和频率轴可用。

`firmware/rf_rebuild` 是反汇编得到的可编译行为对照，包含频率算术、A/B RXON 准备、模式配置、SPI/RFAD 辅助函数和 NV 解析。它没有整体替换厂商冷启动；当前部署服务仍调用必要的厂商初始化和 RX 请求。

UIS8910 SDK 二进制是软件行为的主要依据，固定提交的 ZW217 同代源码提供字段和布局名称，RDA8955/8810/8850e 精选资料只用于结构比较。RF 镜像含旧 PULP 扩展，普通 RISC-V 反汇编不能正确解释所有指令。原生/模拟器逐访问对照证明的是指定输入下的软件行为，不是物理锁定或模拟电路拓扑。

当前六槽总计 49,152 字节；按 `槽总字节/(Fs×4)` 计算，仅相当于 BW0 的 6.4 ms、BW4/5 的 0.4 ms 输出时间容量，并不是测得的端到端延迟。采集到 USB 的设备端不复制 payload；Windows 写盘、插件队列和 CF32 转换仍会复制或运算。没有设备 CPU 百分比实测，不能用“直接 DMA”替代这个指标。

## 4. IQ 格式

每个复数样点 4 字节：

| 字段 | 形式 |
| --- | --- |
| lane0 | little-endian 16 位容器，signed 12 位有效值位于 bits 15:4 |
| lane1 | little-endian 16 位容器，signed 12 位有效值位于 bits 15:4 |
| 交错顺序 | lane0, lane1, lane0, lane1...；不以字段名冒充已确认的物理 I/Q |
| 主机约定 | `int16 >> 4` 后使用 `lane0 - j*lane1` 形成正频率方向 |

物理 I/Q 引脚命名、绝对幅度、ENOB、时钟 ppm 和精确采样间隙尚未完成校准。主机统计可以报告字节、设备完成量和队列丢弃，但不能从字节相等推出没有采集间隙。

## 5. 频率和 RF 路由

用户只设置中心频率，内部 LTE 信道/路由对用户隐藏，Windows、SoapySDR 和 SDR++ 复用共享表与 Auto 辅助代码。工程研究包络约 **687.5–1000 MHz** 与 **1375–2786 MHz**，内部仍是离散点和网格证据，约 1.0–1.375 GHz 之间没有连续接收证明。**1000 MHz 只是软件包络**：970/985 MHz 参考成功；990 MHz 一次失败、较强参考下成功；995/999.9 MHz 未合格。高于 2786 MHz 响应退化，2800 MHz 只有弱 TX 相关响应和退化频移跟随。

本次源码评审还发现一个待统一的交付差异：C++ Soapy/SDR++ 的 B40 Auto 质量上界为 2786 MHz，Windows C 辅助函数仍保留 2790.625 MHz 请求包络。两者都不是物理极限；本轮不修改已测固件/主机二进制。[维护者评审](maintainer-review.md)记录具体来源，不能再声称各入口的边界完全一致。

关键条件：

- B40/BW0：2400–2800 MHz 以 5 MHz 步进 81 点，72 点完整通过；2435/2440 MHz 按用户确认的 Wi-Fi/蓝牙环境影响验收。
- B40 下侧：2000–2390 MHz 以 10 MHz 步进的 40 个点通过，不能排除 10 MHz 间隔的窄空洞。
- B5/B8：880–940 MHz 重叠对照支持 B5 低端、B8 高端的 Auto 滞回；B5 687.5 MHz 有参考成功，681.25 MHz 未识别首音。
- B3：1375、1400、1447、1500、1600、1650、1680、1710、1800/1900 MHz 等代表点有条件证据；1350/1300 MHz 当前条件未检出。

这些结果受当前双频 Wi-Fi 天线、B210 参考信号、线缆/距离、TX 增益和 RX 增益影响，不能写成芯片物理上下限。软件可请求范围、离散 RF 响应、完整参考质量和连续覆盖必须分开。

2535/2545 MHz 的 off/on 检查不完整，2540/2550 MHz 只有单音局部证据，不能自动当完整通过。历史记录中 TRX1 已验证映射为 `A:A A:B / channel0 / TX-RX`；天线距离随实验约 25–50 cm，不能把最新距离倒填到所有历史测试。

## 6. 带宽与 USB 性能

默认每路 12 位数值用 16 位存储，名义速率和全量 raw 预算如下：

| BW | 名义采样率 | 全量 raw 预算 | 历史相对 −3 dB 总宽度 | 当前状态 |
| --- | ---: | ---: | --- | --- |
| BW0 | 1.92 Msps | 7.68 MB/s | 1.05–1.10 MHz，B5 | 10 秒和更长采集已验证 |
| BW1 | 3.84 Msps | 15.36 MB/s | 2.75–2.80 MHz，B5 | 10 秒采集与通信已验证 |
| BW2 | 7.68 Msps | 30.72 MB/s | 4.55–4.65 MHz，B5 | 接近当前供给边界，缺持续余量 |
| BW3 | 15.36 Msps | 61.44 MB/s | 9.2–9.4 MHz，B5 | 部分传输/频谱 |
| BW4 | 30.72 Msps | 122.88 MB/s | 13.6–13.8 MHz，B5 | 部分传输/频谱 |
| BW5 | 30.72 Msps | 122.88 MB/s | 17.5–18.5 MHz，B40 | 部分传输/频谱 |

USB 2.0 High-Speed 的当前实用供给约 30–32 MB/s。BW0/BW1 自动等待约 250 µs，BW2–BW5 约 100 µs；该调度分支已经按工程取舍收口。USB 速度字节不等同 RF 有效通带，宽档只承诺部分输出、频谱刷新、频率轴和停止改参可用。

通带来自固定 RF 音、改变 RX 中心并相对参考归一化的端到端 −3 dB 括限，包含调谐、模拟与数字响应。BW0–4 用 B5、RF 音 881.65 MHz；BW5 用 B40、RF 音 2000.15 MHz；不同历史固件和 RX40/TX20 或40 条件不能当所有路径的统一规格。[性能页](performance.md)链接原始数值。官方 LTE 1.4/3/5/10/15/20 MHz 标称信道宽度与采样率、相对 −3 dB 宽度不是同一指标，不能强行相等。

例如 BW5 的 31.94 MB/s 约为全量 122.88 MB/s 的 26%，是保留下来的样本片段，不是自动变成连续 7.985 Msps。大 FFT 跨过间隙仍可能产生伪影，频谱可用不等于通信数据连续。

## 7. 空口通信功能证明

使用 B210 作为有限发射端、UIS8910 以 RX gain index 30 接收、约 50 cm 双频天线，10 秒实时主机解调结果如下：

| 频率 | BW | 调制 | 帧数 | BER | EVM | 主机丢弃 | 结论 |
| ---: | ---: | --- | ---: | ---: | ---: | ---: | --- |
| 2700 MHz | 0 | QPSK | 2022 | 0 | 4.68% | 0 B | 功能通过 |
| 1900 MHz | 0 | OFDM | 4157 | 0 | 3.15% | 0 B | 功能通过 |
| 1900 MHz | 1 | OFDM | 8320 | 1.56e-5 | 3.04% | 0 B | 功能通过，保留极少误码 |
| 1900 MHz | 1 | QPSK | 2866 | 0 | 10.34% | 59,179,008 B | 有损无线证明，不宣称无损 |

这是 10 秒无线传输能力证明，不是全频率调制成功证明，也不排除模拟压缩、精确 RF 丢样和长时间稳定性问题。所有收发实验从较低 RX 增益开始；没有数字近轨不能排除模拟级压缩。

上述四行源文件帧获取率分别 99.7533%/99.7840%/99.8440%/70.6956%；设备与主机字节差分别 24,576/57,344/49,152/49,152 B。BER 只针对成功解出的数据，不能因 BER0 忽略丢失帧。获取率以源文件完整帧为分母，不是物理 RF 发射帧计数。解调进程 CPU 时间分别约 4.297/7.109/6.547/14.438 s，原生接收器约 0.094/0.109/0.125/0.516 s；约 14.8–15.1 s 的接收墙钟含启动和尾部，不等于 10 秒源时长。[最终通信结论](../records/communication/functional-acceptance.json)保留全部条件。

## 8. 外部前端与寄存器研究边界

SDK/NV 和 ZW217 同代源码表明本机存在 RFFE 初始化、ID 读取和接收开关流程。当前只能说 Air724UG 配置与 **RTM7916-51 兼容性假设**相符；没有物理 ID 读回或 BOM 证据确认确切后缀和板级连线。B5 开关对照没有测得收益，B8 对照不稳定，因此没有据此修改 Auto 默认值。

寄存器地址、字段、参考名和证据等级见 [寄存器与反汇编参考](register-reference.md)。前代 RDA8810/RDA8955 只用于理解代码结构，不能直接移植其 bit 位。

交叉表当前有 129 个条目、51 个具名参考声明和每视图 172 个编译验证字段值，两个地址视图；不是“129 个硬件寄存器均已验证”。RF-local `0x30000`、CP 别名 `0x50030000`、参考 GGE `0x05030000`、RF RAM、RFAD 与外部 RFFE 是不同空间，见[寄存器 CSV](data/rf-registers.csv)和[字段 CSV](data/rf-fields.csv)。

字段CSV当前导出交叉表中的100个具名字段，与原生编译检查172个初始化取值不是同一统计口径，也不是完整芯片寄存器数据库。

频率辅助函数 `0x37f0` 以 100 Hz 为单位，`working_raw<10000000` 时算术输入乘二，默认 D=7（除非相关 NV enable 恰好为1），产生 `Q8=floor(effective_raw×256/260000)` 和 `W=floor(effective_raw×2^28/(260000×D)) mod 2^32` 后写 RAM，再由 RXON 消费。这个函数本身不写 PLL，D=7 时有效域 2912 MHz 的编码回卷不是物理上限。BBPLL lock、VCO 静态码和 cal_ready 都不能充当尚未确认的 RF LO lock。

## 9. 构建、数据保留和开源复现

当前发布统一为v0.1，与原已部署v32字节一致。`tools/build_firmware.py`从源码、`build-support`固定工具包和v0.1平台PAC编译AP/CP并重新封装；独立源码副本构建成功，不依赖旧work或seed。厂商CP/RF/boot/NV仍保留二进制，不是从零替代厂商启动。新编译产物未刷入；`tools/build_capture.py`仅为旧B5研究入口。[构建指南](building.md)与[收敛审计](../records/maintenance/release-v0.1-README.md)说明边界。

用户已明确要求“包括原始 IQ，只保留最终结论”。因此本轮删除 `work/`、`records/` 中的 1,675 个 `.raw/.fc32/.cs16/.iq`，合计 34,852,574,208 B；保留最终数值、测试条件、失败结论和小型历史元数据，未删除源码、工具链、PAC/ELF/.bin 或冻结归档。原始载荷不可从源码恢复，历史结果现在不能直接重算，见[清理审计](../records/maintenance/open-source-preparation-README.md)。

本地完整校验核对保留工作站的身份、文档和旧证据新鲜度；独立源码构建使用另外的固定依赖与构建入口。便携检查核对文档、数据和依赖包，Windows CI配置编译固件，不访问硬件；尚未实际运行GitHub CI。原创代码许可尚未选择，第三方资料不能随意套用同一个 License；详见[许可状态](../LICENSE-STATUS.md)及[第三方来源](../THIRD_PARTY_NOTICES.md)。

## 10. 已知缺口

- 芯片物理频率上下限与连续覆盖未隔离出板级、滤波器、天线和参考信号影响。
- RF LO 的真实 lock 位尚未确认；`rxpll_cal_ready`/`txpll_cal_ready` 是校准状态，BBPLL lock 不能替代 RF LO lock。
- 外部前端确切型号、有效 ID 读回、板级 RFFE 接线未确认。
- ENOB、绝对功率校准、真实 I/Q 极性、精确丢样位置和时钟校准未完成。
- BW2–BW5 的 USB 全量持续传输不可行或缺少余量；BW6/7 没有新增通带证据。
- 当前独立 RF C 重构仍是行为对照，不是完整冷启动替代实现。

噪声系数、SFDR、IIP3、绝对灵敏度、设备 CPU 使用率、绝对时间戳和跨平台原生接收也未测或未交付。开源维护缺口和分级改进任务集中在[维护者评审](maintainer-review.md)，不另启硬件 Goal，也不把文档完成等同整个研究目标完成。
